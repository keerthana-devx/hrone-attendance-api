# REVIEW.md

## Defects found in the starter `app/main.py`

| # | Where | What is wrong | How you'd notice it | How it was fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses naive `punch_in` datetime and replaces hour/minute on it directly, ignoring timezone. Shift times are IST; comparing against a naive local datetime gives wrong results for any server not in IST. | Punch-in at 09:40:01 IST on a UTC server returns 0 late minutes instead of 10. | Converted `punch_in` to IST before building the shift-start datetime; used `datetime(..., tzinfo=IST)` anchored to the attendance date. |
| 2 | `compute_late_minutes` | Grace boundary is wrong. `int(601/60) = 10`, then `10 > 10` is False, so 09:40:01 returns 0 instead of 10. R2 says strictly more than 10 minutes means > 600 seconds. | `punch_in=09:40:01` with shift 09:30 returns `late_minutes=0` instead of 10. | Changed threshold to `elapsed_seconds <= 600` (not late) vs `> 600` (late). |
| 3 | `compute_overtime` | Builds `end` as an aware IST datetime but `punch_out` is naive — mixed aware/naive comparison raises `TypeError`. Also missing the 30-minute minimum (R3). | Any punch-out call crashes with `TypeError: can't compare offset-naive and offset-aware datetimes`. | Made `punch_out` always UTC-aware; built `shift_end_ist` as aware IST; added `>= 30` guard. |
| 4 | `GET /health` | Returns `{"status": "ok"}` unconditionally without pinging MongoDB. | Health check passes even when MongoDB is down; the grader polls this before testing. | Added `client.admin.command("ping")` inside a try/except; returns 503 on failure. |
| 5 | `POST /employees` — race condition | Uses `find_one` then `insert_one`. Two concurrent requests can both pass the check and both insert. | Concurrent duplicate creation yields two 201 responses instead of one 201 and one 409. | Removed the pre-check; rely solely on the unique index and catch `DuplicateKeyError`. |
| 6 | `POST /employees` — `created_at` timezone | `datetime.now()` returns a naive local-time datetime. MongoDB stores it without UTC context. | On a non-IST server the stored time is wrong; PyMongo with `tz_aware=True` may also behave unexpectedly. | Changed to `datetime.now(tz=timezone.utc)`. |
| 7 | `POST /employees` — no validation | `EmployeeIn` has no validators for `emp_code` pattern, email format, field lengths, shift format, or `shift_start != shift_end`. | `POST /employees` with `emp_code="BADCODE"` returns 201 instead of 422. | Added `@field_validator` for every field and a `@model_validator` for the shift-differ rule. |
| 8 | `POST /employees` — `created_at` in response | `created_at` is returned as a Python `datetime` object, not an integer epoch millisecond. | Response JSON contains a datetime string instead of an integer. | `serialize_employee` converts it via `dt_to_ms`. |
| 9 | `GET /employees` — wrong skip | `skip = page * page_size` skips one extra page. Page 1 skips `page_size` items instead of 0. | First page returns items starting from index `page_size`, not 0. | Changed to `(page - 1) * page_size`. |
| 10 | `GET /employees` — `total` ignores filter | `count_documents({})` counts all employees regardless of the `department` filter. | Filtered list returns wrong `total`. | Changed to `count_documents(q)` after building the filter. |
| 11 | `GET /employees` — no sort | No `.sort()` call; order is undefined. | Results are not sorted by `emp_code` ascending as required. | Added `.sort("emp_code", ASCENDING)`. |
| 12 | `POST /attendance/punch-in` — no 404 | `emp = db.employees.find_one(...)` result is never checked for `None`. | Unknown employee causes `TypeError: 'NoneType' object is not subscriptable` instead of 404. | Added `if not emp: raise HTTPException(404, ...)`. |
| 13 | `POST /attendance/punch-in` — naive datetime | `datetime.fromtimestamp(ms/1000)` uses local system time, not UTC. | On a UTC server the stored `punch_in` is correct by accident, but on any other server it is wrong. | Changed to `datetime.fromtimestamp(ms//1000, tz=timezone.utc)` (also truncates to seconds). |
| 14 | `POST /attendance/punch-in` — wrong attendance date | `ts.date()` uses the naive datetime's local date, not the IST date. Overnight-shift logic (R1) is absent. | A punch-in at 00:30 IST (19:00 UTC previous day) gets the wrong attendance date. | Implemented `attendance_date_for_punch` using IST conversion and overnight-shift logic. |
| 15 | `POST /attendance/punch-in` — race condition | `find_one` then `insert_one` check-then-insert. | Concurrent identical punch-ins both succeed. | Removed pre-check; rely on unique compound index `(emp_code, date)`; catch `DuplicateKeyError`. |
| 16 | `POST /attendance/punch-in` — response shape | Response includes `id` (ObjectId string) and exposes `_id`. Contract says no `id` field and no `_id`. | Response has an extra `id` field and `punch_in` is a datetime object, not epoch ms. | Used `serialize_record` which removes `_id` and converts all datetimes to epoch ms. |
| 17 | `POST /attendance/punch-in` — no timestamp validation | No check that `punched_at` is a valid epoch-ms integer (not bool, float, or seconds-range). | `punched_at=true` or `punched_at=1234567` (seconds range) is accepted instead of rejected with 422. | Added `validate_ms` called from the Pydantic `field_validator`. |
| 18 | `GET /attendance` — full collection load | `list(db.attendance_logs.find(q))` loads all matching documents into Python memory. | Slow and memory-exhausting on ~100k records; explicitly forbidden by the contract. | Used server-side `.sort().skip().limit()` and `count_documents(q)` for total. |
| 19 | `GET /attendance` — wrong sort | Python sort only by `date` descending; contract requires `date` desc then `emp_code` asc. | Ties on date are in arbitrary order. | Added `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`. |
| 20 | `GET /attendance` — exposes `_id` | `d["id"] = str(d.pop("_id"))` adds an `id` field and removes `_id`, but the contract has no `id` field. | Response contains an extra `id` field. | Used `serialize_record` which excludes `_id` entirely. |
| 21 | No indexes | No indexes are created at startup. Unique constraints are not enforced; queries do full collection scans. | Concurrent duplicate punch-ins both succeed; analytics are slow on large datasets. | Added `create_indexes()` on the `startup` event. |
| 22 | Missing 7 endpoints | `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, all analytics endpoints, and `GET /admin/explain/{endpoint}` are not implemented. | Any call to these routes returns 404 or 405. | All endpoints implemented. |

## Items examined and determined NOT to be defects

- **`compute_late_minutes` return value**: The function returns `minutes` (elapsed from shift_start), not `minutes - 10`. This is correct per R2 ("whole minutes elapsed since shift_start, not since the end of the grace period"). The only real bug was the timezone issue and the boundary condition.
- **`load_dotenv()` call**: Calling it without `override=False` would override real environment variables with `.env` values. The starter used the default (`override=False` is the default in python-dotenv), so this was not a defect — but the implementation explicitly passes `override=False` for clarity.
- **`PunchInIn` model name**: The starter used `PunchInIn` as the model name. This is an internal name not visible in the API; it is not a defect.
